# mac-controler

맥북 메뉴바에서 맥이 잠드는 조건을 제어한다. 지금 하는 일은 하나다 —
**뚜껑을 닫아도 자지 않게 하기.**

개인용으로 만들었고 배포용 서명이 없다. 아래 [보안](#보안--읽고-쓸-것)을 먼저 읽기를 권한다.

## 왜 root 데몬이 필요한가

뚜껑 닫힘 슬립을 막는 방법은 실질적으로 하나뿐이다 — `SleepDisabled`
시스템 전원 설정이다. `caffeinate` 나 `IOPMAssertion` 계열은 **뚜껑 닫힘을 막지 못한다.**
커널이 `IOPMrootDomain::checkSystemSleepAllowed()` 에서 `userDisabledAllSleep`
을 뚜껑 닫힘 판정보다 먼저 검사하기 때문이다.

`SleepDisabled` 는 root 로만 쓸 수 있고, 문서화되어 있지 않다
(`man pmset` 에 없다). 그래서 구조가 이렇게 된다:

```
MacControler.app  ──XPC──▶  dev.maccontroler.helper
(비특권, 메뉴바)              (root LaunchDaemon)
     정책 판단                   값 하나를 켜고 되돌리기만
```

**정책 판단은 전부 비특권 앱에 있다.** 배터리 임계·외부 디스플레이·개입 필요성
같은 판단을 헬퍼가 하지 않는다. 헬퍼가 할 수 있는 일의 범위가 곧 root 권한의
공격 표면이라서다.

자세한 근거와 실측 기록은 [DESIGN.md](DESIGN.md) 에 있다.

## 요구사항

| | |
|---|---|
| macOS | 26 이상 (`Package.swift` 가 `.macOS(.v26)`) |
| 툴체인 | Xcode 26 / Swift 6.2 이상 |
| 검증 환경 | Apple Silicon, 노치 있는 MacBook Pro |

`.xcodeproj` 가 없다. SwiftPM 이 바이너리를 만들고 `Scripts/bundle.sh` 가
`.app` 번들을 조립한다.

## 설치

```bash
make app                  # dist/MacControler.app 조립
sudo make install-helper  # root 헬퍼 설치 + launchd 등록
make run                  # 앱 실행
```

지우려면:

```bash
sudo make uninstall-helper
```

`uninstall-helper` 는 헬퍼를 내리기 **전에** 슬립 설정을 원래 값으로 되돌리고,
커널과 디스크 양쪽에서 확인될 때까지 기다린 뒤에야 파일을 지운다.
확인에 실패하면 헬퍼를 다시 띄운다 — 흔적을 남기고 사라지지 않기 위해서다.

## 쓰는 법

메뉴바 아이콘이 상태다.

| 아이콘 | 뜻 |
|---|---|
| 🌙 `moon.zzz` | 이 앱은 아무것도 막고 있지 않다 |
| ☀️ `sun.max.fill` | 이 앱이 슬립을 막고 있다 |

기준은 "우리가 켰는가" 다. 외부 디스플레이 때문에 안 자는 경우나 다른 도구가
켜둔 `SleepDisabled` 는 해로 표시하지 않는다 — 그러면 이 앱이 지금 일하고
있는지를 아이콘으로 알 수 없다.

메뉴를 열면 뚜껑·전원·외부 디스플레이·슬립 차단 상태를 한 화면에서 볼 수 있고,
맨 아래 토글로 켜고 끈다. 켜져 있으면 언제 자동 해제되는지도 함께 뜬다.

> 아이콘이 안 보이면 노치에 가려 있을 수 있다. 앱이 스스로 감지해 메뉴에
> 알린다. 메뉴바 아이콘을 ⌘-드래그해 자리를 만들면 된다. 상태 아이템 위치는
> macOS 가 정하고 앱이 지정할 수 있는 API 가 없어서, 고치는 대신 알린다.

## 안전장치

`SleepDisabled` 는 뚜껑 닫힘뿐 아니라 유휴 슬립과 Apple 메뉴 > 잠자기까지
전부 막는 **시스템 전역 킬스위치**다. 켜둔 채 잊으면 가방 속에서 방전된다.
그래서 세 겹으로 막는다.

| 안전장치 | 언제 | 끌 수 있나 |
|---|---|---|
| 하트비트 워치독 | 앱이 90초간 응답 없으면 헬퍼가 복원 | ✗ |
| 부팅 세션 고아 복구 | 재부팅을 건너뛴 흔적을 기동 즉시 복원 | ✗ |
| 배터리 임계 | 잔량 15% 미만이면 해제 + 알림 | ✗ |
| 시간 상한 | 정해진 시간이 지나면 해제 | ✓ 설정 창 |

**복원은 항상 baseline 으로 한다.** 무조건 `false` 로 덮지 않는다 —
다른 도구나 사용자가 켜둔 설정을 파괴하지 않기 위해서다. 켜기 **전에** 현재
값을 디스크(`/Library/Application Support/dev.maccontroler/baseline.json`)에
저장하고, 그것으로만 되돌린다.

배터리 전원에서 켜려고 하면 확인 다이얼로그가 먼저 뜬다.

## 설정

메뉴 → `설정…` (또는 ⌘,)

시간 상한을 30분 / 1시간 / 2시간 / 4시간 / 8시간 / **꺼짐** 중에서 고른다.
기본값은 4시간이다.

'꺼짐' 은 **시간 상한만** 끈다. 위 표의 나머지 셋은 그대로 동작한다.
다만 앞의 둘은 헬퍼가 살아 있을 때만 동작하고, 시간 상한은 헬퍼까지 반복해서
죽는 드문 경우의 마지막 방어선이다 — '꺼짐' 은 그것까지 없앤다. 설정 창이
이 사실을 그대로 적어 둔다.

고른 값은 앱과 헬퍼 양쪽에 저장된다. 헬퍼가 재시작해도, 앱이 죽어도 지켜진다.

## 개발

```bash
make test           # swift test
make build          # 바이너리만
make run            # 재빌드 + 재실행
make verify         # 시스템에 실제로 반영된 값 (앱 표시와 무관하게 이게 진실)
make limit          # 지금 걸려 있는 자동 해제 상한
make helper-status  # launchd 등록 상태
make logs           # 앱 로그 스트림
make logs-helper    # 헬퍼 로그 스트림
make ax-verify      # 접근성 API 로 메뉴 항목 나열 (노치에 가려도 동작)
```

`make ax-verify ITEM="지금 새로고침"` 처럼 항목을 주면 눌러본다. 항목 없이 부르면
읽기 전용이며, 그래도 앞뒤 `SleepDisabled` 를 비교해 값이 바뀌면 크게 알린다.

### 뚜껑 닫힘 테스트

뚜껑 닫기는 소프트웨어로 흉내낼 수 없다(`IOPMTestClamshellClose` 는 DEBUG
커널 전용). 실제로 닫아 보는 수밖에 없다.

```bash
./Scripts/clamshell-test.sh            # 토글 켠 상태 — 안 자야 성공
./Scripts/clamshell-test.sh --control  # 대조군: 토글 끈 상태 — 자야 성공
./Scripts/sleepgate-test.sh            # 커널 슬립 게이트만 확인 (뚜껑 안 닫음)
```

닫힌 상태 샘플이 하나도 없으면 "테스트 무효" 로 끝난다. 검증 없이 통과를
보고하지 않기 위해서다.

## 보안 — 읽고 쓸 것

**이 헬퍼는 XPC 피어를 검증하지 않는다.** 개발 환경에 유효한 코드서명 신원이
없어서, 연결해 온 프로세스가 정말 이 앱인지 암호학적으로 확인할 방법이 없다.
즉 **같은 맥의 어떤 로컬 프로세스든 헬퍼에 명령할 수 있다.**

그 전제에서 유일한 방어는 "헬퍼가 할 수 있는 일을 최소화하는 것" 하나다.
헬퍼의 엔드포인트는 넷뿐이고(`engage` / `release` / `heartbeat` / `status`),
할 수 있는 일은 `SleepDisabled` 를 켜고 baseline 으로 되돌리는 것뿐이다.
임의 명령 실행도, 파일 접근도, 다른 설정 변경도 없다.

### 악성 로컬 프로세스에 대해 실제로 남는 방어

위 [안전장치](#안전장치) 표는 **앱을 통해 쓸 때** 이야기다. 앱을 거치지 않고
헬퍼에 직접 붙는 프로세스에는 그대로 적용되지 않는다. 정직하게 갈라 적는다.

| 안전장치 | 어디에 있나 | 악성 피어에게 |
|---|---|---|
| 배터리 15% 해제 | **앱** (`ClamshellPolicy`) | ✗ 적용 안 됨 |
| 시간 상한 | 헬퍼가 지키되 **값은 피어가 정한다** | ✗ `never` 로 끌 수 있음 |
| 하트비트 워치독 90초 | 헬퍼 | △ 하트비트를 계속 보내면 발동 안 함 |
| 부팅 세션 고아 복구 | 헬퍼 | ✓ 재부팅하면 반드시 되돌아감 |

즉 악의적인 로컬 프로세스는 **재부팅 전까지 맥을 계속 깨어 있게 만들 수 있다.**
그것이 이 구조에서 할 수 있는 최대치이기도 하다 — 임의 명령 실행도, 파일
접근도, 다른 설정 변경도 없다. 그래도 이 코드를 가져다 쓸 생각이라면 알고
있어야 한다:

- 배포하려면 Developer ID 서명 + 공증 + `SMAppService` 로 바꿔야 한다.
  그러면 `SMAppService` 가 피어 검증을 대신 해 준다.
- LaunchDaemon 은 `/Library/LaunchDaemons` 에 있고 root:wheel 소유다.
  그 경로에 쓸 수 있는 사람은 이미 root 이므로 권한 상승 경로는 아니다.
